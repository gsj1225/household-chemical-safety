# 家庭化学品安全管理方案

> 版本：v2.0（家庭化学品库，已确认）
>
> 日期：2026-08-02
>
> 状态：产品方案已确认；下一阶段为低保真线框图。

## 一、比赛方向

- 赛道：家庭化学品安全。
- 核心任务：帮助普通家庭识别、记录和持续管理清洁剂、消毒剂、洗衣化学品、杀虫用品等常见家庭化学品。
- 价值重点：不把“识别出商品名称”当作创新终点，而是把识别结果转化为可维护的家庭化学品档案，并持续检查库内产品之间的潜在相容性问题。

## 二、产品定位

> 用户扫描一次产品，核对后加入“我的化学品库”；以后可以查看、补充、修改或删除产品信息。每次新增或更新产品，系统都会重新检查它与库内其他产品之间的潜在混用和储存禁忌。

正式项目表述：**家庭化学品安全管理系统**。

核心用户功能：**我的化学品库**。

主要操作：**扫描入库**。
关系能力：**库内相容性检查**。

价值主张：

> 扫描一次，长期留档；每增加一种化学品，重新检查一次库内相容性。

## 三、方向变更

v2.0 不再以以下内容作为产品主线：

- 不再要求用户先拍全景图，再按区域细拍。
- 不再以一次性 challenge、排雷评分或历史报告作为主要数据结构。
- 不再使用 SBTI、人格类型或娱乐化测试作为核心表达。
- 不记录产品当前位于厨房、卫生间或某个柜子的真实位置。
- 不通过产品共同存在于库中，直接断言用户正在混用或错误存放。

保留并继续发展的能力：

- 产品正面、背标、成分和警示文字识别。
- 用户核对后再写入正式数据。
- 规则引擎、风险证据和资料来源。
- 产品之间的成分冲突和使用禁忌检查。
- 图片隐私、错误恢复和不确定性表达。

## 四、目标用户

- 家中存有多种清洁剂、消毒剂、洗衣用品或杀虫用品，希望集中管理的普通用户。
- 不熟悉化学品成分，但希望快速了解标签、储存条件、有效期和不可混用关系的用户。
- 希望再次扫描时复用已有记录，而不是每次重新生成一次性报告的用户。

主要设备为手机，核心操作应支持单手完成。

## 五、首期产品范围

### 5.1 优先纳入

1. 厨房和卫生间清洁剂：洗洁精、油污清洁剂、洁厕剂、除垢剂、管道疏通剂等。
2. 消毒与漂白产品：含氯消毒剂、漂白剂、酒精和表面消毒剂等。
3. 洗衣化学品：洗衣液、洗衣凝珠、衣物漂白剂、柔顺剂、去渍剂等。
4. 家庭杀虫产品：杀虫喷雾、蟑螂药、蚊香、驱虫液和老鼠药等。

### 5.2 后续扩展

- 胶黏剂、油漆和稀释剂。
- 汽车养护液。
- 园艺农药和肥料。
- 固体酒精、气罐等易燃家用品。

### 5.3 暂不纳入

- 普通食品和调味料。
- 药品、保健品和医疗诊断。
- 化妆品的完整功效或人体适用性评估。
- 工业化学品和实验室化学品。

食醋、小苏打等普通食品在被用户作为清洁剂使用时，可作为相容性检查的辅助对象，但不默认作为家庭化学品库存。

## 六、核心对象

### 6.1 库存产品

每一件入库产品至少包含：

| 字段 | 说明 |
|---|---|
| 产品照片 | 用户选定的仓库封面照片，长期展示 |
| 品牌与产品名 | 识别后由用户核对 |
| 产品类别 | 清洁剂、消毒剂、杀虫剂等 |
| 生产日期 | 允许未知或手动修正 |
| 有效期/保质期 | 允许未知；不从模糊喷码猜测 |
| 成分 | 只保存照片可见或用户确认的信息 |
| 包装警示语 | 来自标签的结构化摘要 |
| 储存条件 | 优先记录标签要求，系统建议单独标记 |
| 危险性 | 风险类型、等级、依据和适用边界 |
| 不相容对象 | 不可混用或不建议共同存放的成分/产品类型 |
| 识别置信度 | 高、中、低或待补充 |
| 更新时间 | 用于提醒信息可能过期 |

系统不记录产品的实时物理位置。储存字段回答“应该如何储存”，不回答“现在放在哪里”。

### 6.2 相容性关系

相容性关系连接两个库内产品或产品与一类成分，至少包含：

- 关系类型：禁止混用、不建议连续使用、建议分开储存、信息不足。
- 触发依据：产品标签、已确认成分和规则编号。
- 风险说明：条件式表达可能后果，不把潜在关系写成已经发生的事故。
- 用户动作：查看标签、避免混用、遵循冲洗间隔、补充信息等。
- 证据状态和资料来源。

“库内存在两件不相容产品”只表示需要提醒，不表示用户当前把它们放在一起或正在混用。

## 七、核心功能

### 7.1 扫描入库

1. 用户拍摄产品，或从相册选择产品照片。
2. 系统识别品牌、名称、品类和可见标签信息。
3. 如果生产日期、有效期、成分或警示语看不清，系统明确标记未知，并提示补拍背标或手动填写。
4. 用户核对并修正信息。
5. 系统检查是否疑似重复产品。
6. 用户选择更新原记录、增加另一件产品或取消。
7. 用户选择仓库封面照片并确认入库。
8. 系统保存产品，并重新执行库内相容性检查。

### 7.2 我的化学品库

仓库负责展示所有有效库存产品，并提供：

- 查看产品摘要。
- 搜索和筛选。
- 打开产品详情。
- 进入扫描入库。
- 查看库内相容性提醒。

产品方已提出“双列产品陈列、使用入库照片、卡片下方展示摘要”的页面方向。具体卡片比例、信息密度和滚动方式在低保真线框图阶段确认，本方案不提前锁定视觉样式。

### 7.3 产品详情与增删改查

- 查看完整照片和结构化产品信息。
- 编辑识别字段、生产日期、有效期、储存条件和危险性说明。
- 重新扫描标签以补充信息。
- 查看该产品与库内其他产品的相容性关系。
- 删除错误记录。

删除前必须说明：相关相容性结果也会移除。删除产品时同步删除由应用保存的本地封面缩略图。

### 7.4 库内相容性检查

- 每次新增、修改或删除产品后重新计算受影响的关系。
- 仓库摘要显示需要关注的关系数量。
- 产品详情列出具体相关产品、规则、原因和建议。
- 首期不要求绘制复杂网络图；是否增加图形化关系视图留到后续验证。

## 八、图片与隐私

v2.0 因仓库陈列需要长期保留一张产品封面照片，调整原有“请求结束即丢弃全部照片”的策略：

- 用户在入库确认时明确选择并授权保存封面照片。
- 默认保存裁切或压缩后的产品缩略图，不保存全尺寸扫描原图。
- 优先保存在设备本地；云同步不属于首期范围。
- 图片应尽量只包含产品，减少家庭环境背景。
- 删除产品时同步删除应用管理的缩略图。
- 识别失败、取消入库或未确认的照片不进入长期仓库。

## 九、可信表达原则

1. AI 负责识别可见信息，不能直接生成无依据的安全结论。
2. 用户确认后的结构化信息才能进入库存和相容性计算。
3. “未命中规则”不等于产品绝对安全。
4. “库内存在潜在禁忌”不等于用户正在混用。
5. 标签要求、系统建议和用户手动填写必须区分来源。
6. 模糊日期、未知成分和低置信度信息必须如实显示，不得猜测。
7. 建议不能替代产品标签、实验室检测、医疗诊断或专业应急意见。

## 十、产品创新

项目的创新点不表述为“使用视觉模型识别产品”，而是：

1. 从一次性识别升级为持续维护的家庭化学品数字库存。
2. 从单品查询升级为库内多产品相容性检查。
3. 将图片信息、用户确认、可审查规则和证据来源组合为可信判断链。
4. 通过再次扫描复用和更新已有记录，形成长期安全管理，而不是一次性报告。

答辩概括：

> 传统识别工具回答“这是什么”，本项目进一步保存“我家有哪些”，并持续检查“它和家里已有产品之间有什么需要避免的关系”。

## 十一、MVP范围

首期只实现：

1. 产品拍摄/相册输入与识别。
2. 信息核对、补充和重复产品分支。
3. 产品封面缩略图保存。
4. 我的化学品库列表。
5. 产品详情、编辑和删除。
6. 库内两两相容性规则检查。
7. 加载、空、错误、权限和删除确认状态。

首期不实现：

- 全景区域识别。
- SBTI或人格标签。
- 排雷分数、排行榜和社交挑战。
- 真实存放位置追踪。
- 账号、家庭成员共享和云端同步。
- 复杂关系网络图。
- 自动推断用户正在混用产品。
