# 知识库优先的家庭化学品助手 — 用户流程与安全架构

> 版本：v1.0 Draft  
> 日期：2026-08-12  
> 状态：Stage 1，待确认  
> 变更说明：本方案会使原有问答 Stage 4 实施方案失效，需要重新设计检索、依据展示和测试。

## 1. 产品目标

让用户在问答页询问家庭清洁问题时，获得三类信息的综合回答：

1. **家庭安全知识库**：我们预先审核、维护的常见污渍、材质、表面和家庭清洁处理知识；
2. **我的化学品库**：用户已经登记并确认过的产品，以及这些产品之间的相容性关系；
3. **受控外部资料**：本地知识不足时，从允许的官方或产品原始来源中检索补充信息。

核心承诺：

> LLM 负责理解问题和组织答案，不负责凭空发明清洁方法；本地安全规则和已审核知识优先于模型自由发挥。

## 2. 当前状态（AS-IS）

当前问答已经支持：

- 文字和照片输入；
- 读取库存产品和产品字段；
- 读取相容性关系；
- 通过 LLM 生成结构化回答；
- 后端过滤未知产品、禁止混用和超范围问题。

当前缺口：

- 没有可独立维护的常见污渍/材质知识库；
- LLM 只能依赖提示词和库存上下文，缺少稳定的生活处理依据；
- 回答没有清楚区分“本地知识库结论”和“模型生成的通用建议”；
- 没有外部资料的受控检索、来源白名单、引用和失败状态；
- 无法审查某条建议的适用材质、禁用条件和更新时间。

## 3. 目标流程（TO-BE）

```text
用户发送文字/照片
        ↓
问题理解：任务、污渍、材质、表面、已使用产品、风险词
        ↓
本地知识库检索
        ├─ 高置信度命中：使用已审核知识，不访问外部网络
        └─ 无命中/低置信度：进入受控外部资料检索
                         ↓
                  来源白名单与内容过滤
                         ├─ 找到可靠资料：标记“外部资料”并引用来源
                         └─ 找不到可靠资料：明确说明信息不足
        ↓
读取我的化学品库 + 相容性关系
        ↓
确定性安全编排
        ├─ critical 禁止关系：覆盖所有普通建议，不给混用/连用步骤
        ├─ 产品信息不足：只能标记“待补充”，不能推荐使用
        ├─ 知识适用条件不满足：删除该方法，不强行套用
        └─ 事故/医疗/中毒：直接安全拒答
        ↓
LLM 组织最终回答
        ↓
展示：回答 + 仓库产品建议 + 通用方法 + 安全提醒 + 知识来源
```

## 4. 本地知识库的内容范围

首期不追求覆盖所有清洁技巧，而是建立少量、可审核、可追溯的常见任务条目。

建议首批主题：

- 油脂类污渍；
- 血液、奶渍等蛋白类污渍；
- 咖啡、茶和食物色渍；
- 墨水和笔迹；
- 化妆品污渍；
- 胶渍和贴纸残留；
- 水垢和皂垢；
- 霉斑；
- 铁锈类污渍；
- 厨房台面、玻璃、瓷砖、金属等常见表面。

每个主题必须记录：

- 可识别的别名和用户说法；
- 适用材质/表面；
- 不适用材质/表面；
- 建议的处理顺序；
- 可关联的产品类别，而不是直接假定某个具体产品；
- 需要查看产品标签的条件；
- 局部测试、通风、防护等前置要求；
- 禁止混用和禁止操作；
- 停止条件；
- 来源、审核人、审核日期、版本号；
- 置信等级。

知识库条目不能只写一段自然语言。建议使用结构化记录：

```json
{
  "id": "stain-oil-on-washable-fabric",
  "topic": "油脂类污渍",
  "aliases": ["油污", "食用油", "油渍"],
  "materials": ["可水洗织物"],
  "excluded_materials": ["需干洗面料", "未经确认的特殊面料"],
  "steps": [
    {"order": 1, "text": "先吸附或轻按，不要反复摩擦"},
    {"order": 2, "text": "按照物品标签选择适用的清洁产品"},
    {"order": 3, "text": "在不显眼处进行局部测试"}
  ],
  "allowed_product_categories": ["laundry", "stain_remover"],
  "warnings": ["先确认材质和产品标签"],
  "prohibited_actions": ["不得混合不同清洁产品"],
  "sources": [{"type": "local_kb", "title": "家庭安全知识库", "url": ""}],
  "reviewed_at": "2026-08-12",
  "version": "1.0",
  "confidence": "reviewed"
}
```

## 5. 检索优先级

### 第一层：本地家庭安全知识库

- 先做关键词、别名、材质和场景匹配；
- 后续可增加向量检索，但不能绕过结构化适用条件；
- 高置信度命中时不访问外部网络，保证回答稳定、可控、低延迟；
- 知识库内容必须可以在代码仓库中审查和版本管理。

### 第二层：我的化学品库和相容性规则

- 根据知识条目的允许产品类别筛选用户库存；
- 再读取产品标签、成分、危险性和储存条件；
- `CompatibilityEngine` 进行最终复核；
- “知识库建议适合某类产品”不等于“用户库存中的某个具体产品一定适合”。

### 第三层：受控外部资料

只有在本地知识库无命中或置信度不足时才触发，且必须满足：

- 使用来源白名单，不接受任意论坛、短视频、营销软文作为安全依据；
- 优先官方机构、公共卫生/疾控机构、产品制造商标签和正式技术资料；
- 外部内容先提取为候选资料，再由本地安全编排层过滤；
- 外部资料不能覆盖本地 `CompatibilityEngine` 的 critical 规则；
- 返回来源标题、网址、检索时间和“外部资料”标签；
- 外部检索失败或来源不可靠时，明确返回“暂无足够依据”，不能让 LLM 自由补全。

外部搜索不是“让大模型随便上网找答案”。它应是一个可关闭、可限流、可审计的后端能力，建议用环境变量控制：

```text
EXTERNAL_KNOWLEDGE_ENABLED=false
EXTERNAL_KNOWLEDGE_ALLOWLIST=...
EXTERNAL_KNOWLEDGE_TIMEOUT_SECONDS=...
```

首个上线版本可以先关闭外部检索，只上线本地知识库；确认来源和预算后再开启。

## 6. 最终回答结构

助手回复应显示来源分层：

```text
助手：根据你提供的“棉质衣物 + 油污”，我先检查了家庭安全知识库。

【知识库建议】
先吸附污渍，确认洗涤标签后再选择适用产品，并先做局部测试。

【结合我家仓库】
蓝月亮洗衣液：可作为候选，但仍需以标签和局部测试为准。
威白洁厕灵：不建议用于衣物，产品类别和材质不匹配。

【相容性提醒】
不要将不同清洁产品混合使用。

【来源】
家庭安全知识库 · stain-oil-on-washable-fabric · v1.0
```

如果使用了外部资料：

```text
【外部资料补充】
本地知识库没有覆盖该材质，以下内容来自经审核的外部资料。
[来源标题] [网址] [检索日期]
```

## 7. 安全边界

- 本地知识库、产品标签和相容性规则优先于 LLM；
- 未知材质、未知成分或来源不足时，必须追问、降级或拒答；
- 不能把“没有查到禁忌”说成“绝对安全”；
- 不能建议混合产品；
- 不能从通用知识自动推导出某个库存产品的具体用量或浓度；
- 除非产品标签明确提供，否则不生成精确稀释比例、接触时间或危险操作参数；
- 误食、中毒、吸入、身体不适等问题继续走超范围拒答；
- 所有具体建议必须能追溯到知识条目、库存字段、相容性规则或外部来源。

## 8. 状态变化

| 状态 | 主要动作 | 用户看到的依据 |
|---|---|---|
| 本地知识命中 | 查看回答和库存关联产品 | “家庭安全知识库” |
| 本地命中但库存不匹配 | 查看通用方法/修改问题 | 知识条目 + “库存无合适产品” |
| 本地知识不足，外部检索中 | 等待或取消 | “正在查找经审核资料” |
| 外部资料命中 | 查看补充回答和来源 | “外部资料”+网址+日期 |
| 外部资料不可靠/无结果 | 修改问题或补充材质 | “暂无足够依据” |
| 相容性 critical | 查看禁止关系 | 本地规则优先，隐藏操作步骤 |
| 信息不足 | 回答材质/成分追问 | “需要补充信息” |
| 超出范围 | 查看拒答和求助提示 | 不显示产品建议和外部操作方法 |
| 网络/API失败 | 重试 | 保留用户问题和照片 |

## 9. 非目标

- 不把知识库做成百科全书；
- 不在首期自动抓取和永久保存任意网页；
- 不允许外部网页直接写入知识库；
- 不让大模型凭生活经验批量生成未经审核的安全规则；
- 不替代产品标签、专业清洁服务、医疗或事故处置机构。

## 10. Stage 1 确认清单

- [ ] 知识库优先于 LLM 自由回答；
- [ ] 知识库内容使用结构化条目，并保存适用材质、禁用条件、来源和审核日期；
- [ ] 先结合知识库，再结合用户库存和相容性引擎；
- [ ] 本地知识库无可靠命中时，才允许受控外部检索；
- [ ] 外部检索使用来源白名单、引用和限流，不能直接信任任意网页；
- [ ] `CompatibilityEngine` 始终拥有最高安全优先级；
- [ ] 首期先上线本地知识库，外部检索默认关闭，验证后再开启；
- [ ] 回复明确展示“知识库来源 / 我的仓库 / 外部资料”；
- [ ] 确认后进入 Stage 2，重新设计问答结果和来源卡片；
- [ ] 在确认前不修改现有问答 UI、Store、API 或业务代码。
