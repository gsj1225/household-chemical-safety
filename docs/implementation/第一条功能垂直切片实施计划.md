## 一、目标

在不改变后端接口和扫描业务流程的前提下，用新组件架构完整迁移：

```text
全景输入
  → 相机或相册
  → 分析中
  → 找到区域：进入原有区域引导
  → 零区域：保留原图并原地恢复
```

这条链路同时验证照片输入、加载反馈、权限、错误恢复、原图上下文和双入口汇合，是最适合作为首个代表性切片的流程。

## 二、范围

### 令牌与基础组件

- 新增原始、语义、组件三层令牌。
- 保持 `colors.ts`、`spacing.ts` 现有导出兼容。
- 实现 `AppText`、`AppButton`、`Surface`、`StateMessage`。
- 实现 `PhotoFrame`、`PhotoInputActions`。

### 功能视图

- `CameraCapture` → `CameraCaptureView`
- `PanoramaView` → `PanoramaInputView`
- `AnalysisView` 独立成文件并保留原图背景。
- `EmptyPanoramaView` → `PanoramaEmptyView`
- `FinishingView` 独立为 `ReportGeneratingView`，只完成文件职责拆分，不做报告视觉迁移。

### 页面控制器

- `ScanScreen` 只调整视图导入与名称。
- `handleCapture`、`handleSelectFromAlbum`、API 请求顺序和状态迁移保持不变。

## 三、非目标

- 不修改后端、API 参数、扫描状态枚举和 Zustand。
- 不迁移区域引导、识别确认、单品结果、报告、历史或首页。
- 不确定最终品牌色、插画、图标、阴影和动效风格。
- 不增加新的第三方依赖。
- 不在本切片抽取 `useScanController`。

## 六、无障碍检查

- `AppButton` 使用按钮角色，加载和禁用通过 `accessibilityState` 表达。
- 主要按钮最小高度 52，其他可点区域最小 44。
- 图片提供用途说明；分析状态提供可朗读文本。
- 权限和错误状态不只依赖颜色。
- 减少动态效果开启时停止循环位移、缩放、旋转和扫描线。
- 长文本允许换行，不让底部按钮遮挡正文。

## 七、平台检查

- 手机基准：390×844。
- Web 宽屏：内容最大宽度保持现有 720，不拉伸成桌面页面。
- 相机 Web 演示入口继续保留。
- 相册取消返回 `null`，不进入分析状态。

## 八、回退策略

- 旧主题导出保持兼容，未迁移页面不受影响。
- 新功能视图只替换 `ScanScreen` 导入，回退无需修改 API、Store 或数据。
- 不删除旧组件，直到新切片完成全部验证；确认无引用后再清理。
