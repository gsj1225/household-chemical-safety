## 一、目标与完成定义

把报告页原有“按钮名是分享卡、实际只发文字”的行为升级为可预览、可通过系统面板分享、可主动保存到相册的隐私图片卡，同时不改变单场景检查、评分和风险规则。

完成定义：

- 报告页能打开完整 3:4 分享卡预览。
- Android/iOS 生成 `1080×1440 PNG`，支持系统图片分享与相册保存。
- Web 保留预览并诚实降级为文字摘要。
- 卡片不包含原图、产品名、地址、证据链接、挑战 ID 或请求信息。
- TypeScript、隐私单测、现有恢复测试、后端测试和 Web 导出通过。

## 二、范围与非目标

包含公开 DTO、黑白卡片、全屏预览、截图服务、系统分享、相册权限与保存、Web 降级、反馈状态、单测和文档。

不包含公共落地页、二维码、账号、云存储、传播数据埋点、外部平台 SDK、后端生成海报、原图分享、完整异常恢复续建和视觉动效精修。

## 四、平台与权限

- Expo SDK 固定 57；使用 SDK 兼容版本 `react-native-view-shot 5.1.0`、`expo-sharing ~57.0.7`、`expo-media-library ~57.0.3`。
- 不在应用启动时请求相册权限；只在用户点击“保存到相册”后请求写入照片权限。
- 分享无需读取相册，直接分享应用缓存中的 PNG。
- Web 不使用本地文件 URI 分享；只调用既有系统文字分享能力。

## 五、可访问性与隐私

- 卡片提供完整朗读标签；按钮使用动作完整名称，处理中声明 busy/disabled。
- 反馈区使用 polite live region；取消分享不清空报告或卡片。
- 分享前必须看到公开内容与隐私边界；保存权限被拒后仍可分享。
- 新公开字段需要同步更新流程、隐私说明和白名单测试。

## 六、回退与后续

- 可按 `ResultScreen` 入口回退到文字分享，不影响扫描、报告或历史。
- 原生模块异常时不允许绕过白名单上传到后端生成图片。
- MVP 后续顺序：Android/iOS 真机验收 → 分享卡小范围用户测试 → 再补细拍/确认/报告异常恢复 → 最终视觉与传播数据迭代。
