## 一、切片目标

以“首页创建失败 → 全景拍摄/相册 → 全景分析失败或照片无效 → 原地恢复”为第一条代表性切片，验证以下架构决策：

1. 错误协议、用户文案和恢复 UI 三层分离。
2. 页面短期保留失败照片与重试上下文，不写入 Zustand 或后端。
3. 可恢复错误不再使用系统 `Alert`，而是在当前页面就地恢复。
4. 网络、超时和临时服务错误优先重试同一张照片。
5. 图片格式、大小或内容无效时优先重拍或从相册换图。
6. 每个页面只有一个主操作，请求进行中禁止重复提交。

## 二、范围

### 包含

- `ApiError` 保留结构化字段，移除“API 地址”等开发语言。
- 新增 `AppFailure`、`toAppFailure()` 和 `getRecoveryCopy()`。
- 新增共享组合组件 `RecoveryPanel`。
- 新增 `PanoramaRecoveryView`，保留全景图并提供语义恢复事件。
- `HomeScreen` 的创建失败由系统弹窗迁移为页面内恢复。
- `ScanScreen` 的全景失败由回空白入口迁移为保留原图的恢复状态。
- 图片无效与网络失败使用不同的主操作层级。
- 补充错误映射和纯函数单元测试。
- 对首页与全景恢复状态做 Web 实际渲染和 Android 手工验收准备。

### 不包含

- 细拍识别失败、确认写入失败和报告生成失败；它们属于后续切片。
- 相机权限、相册权限和退出确认行为。
- 后端错误信封、风险规则、评分、AI 提示词和证据数据。
- 跨应用重启保存照片或恢复未完成会话。
- 最终色板、插画、图标、阴影、圆角细节和动效精修。
- Git 提交、推送或 GitHub 更新。

## 三、AS-IS 与 TO-BE

| 节点 | AS-IS | TO-BE |
|---|---|---|
| 首页创建失败 | `Alert.alert` 覆盖首页 | 首页内容保留，按钮附近显示 `RecoveryPanel` |
| 全景请求失败 | 弹窗后回空白全景入口 | 保留刚才照片，主操作“重试分析这张照片” |
| 无效全景照片 | 与网络失败使用同一流程 | 保留无效照片供核对，主操作“重新拍一张” |
| 错误字段 | `message` 混合追踪号和开发文案 | `AppFailure` 保存事实，文案映射生成用户解释 |
| 重复请求 | 页面局部布尔值不统一 | 每个操作使用明确 `pending` 状态并禁用恢复动作 |

## 四、架构变化

```text
ApiError
  └── toAppFailure(error)
        └── AppFailure(kind/code/requestId/retryAfter)
              └── getRecoveryCopy(operation, failure)
                    └── Screen Controller
                          ├── RecoveryPanel
                          └── PanoramaRecoveryView
```

- `api.ts` 只处理协议、超时、上传和错误字段。
- `recovery.ts` 保存无副作用错误分类与用户文案映射。
- `RecoveryPanel` 只负责语义显示、动作层级和可访问性。
- `HomeScreen`、`ScanScreen` 负责请求、重试、页面状态和导航。
- `PanoramaRecoveryView` 不读取 API、store 或 navigation。

## 五、目标接口

```ts
type RecoverableOperation = 'start' | 'panorama';

type FailureKind =
  | 'network'
  | 'timeout'
  | 'rate_limited'
  | 'invalid_photo'
  | 'challenge_expired'
  | 'service'
  | 'unknown';

type AppFailure = {
  kind: FailureKind;
  code?: string;
  requestId?: string;
  retryAfterSeconds?: number;
};

type PanoramaRecoveryState = {
  failure: AppFailure;
  imageUri: string;
};
```

## 八、可访问性检查

- 错误由符号、标题、正文共同表达，不只靠颜色。
- `RecoveryPanel` 新错误使用 live region 播报一次。
- 追踪号仅作为辅助信息，不重复朗读。
- 主操作名称包含动作和对象，例如“重试分析这张全景照片”。
- 所有动作触控区域至少 44×44。
- 加载时按钮保留尺寸、显示明确文字并禁止重复触发。
- 系统字体放大和长中文时页面允许滚动，底部动作不遮挡内容。

## 九、响应式与平台检查

- Android 390×844：安全区、滚动、底部动作、拍照与相册返回。
- Android 小屏：内容可滚动且操作不裁切。
- Expo Web 1280×900：内容保持最大 720px，不拉伸照片。
- Web 与 Android 共用恢复语义；相机和相册继续走现有平台适配。

## 十、回退策略

- `ApiError` 新字段保持可选，现有调用点继续可以读取 `message`。
- 首页和全景分别迁移；任一入口失败可单独回退到旧分支。
- 不改变 API 请求参数、后端状态或 Zustand 持久数据。
- 新组件均为新增文件，回退时不会影响已有报告、风险卡和历史页面。
- 本切片不删除细拍、确认、报告仍在使用的旧错误处理。
