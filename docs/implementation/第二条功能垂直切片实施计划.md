## 一、目标

在不改变后端接口、扫描状态枚举和风险判断逻辑的前提下，用已确认的新组件架构迁移：

```text
原全景图区域引导
  → 拍摄或选择当前区域照片
  → 单品识别中
  → 产品事实核对与修正
  → 确认后进入现有本地风险评估
```

这条链路验证原图标注、区域进度、等价照片入口、表单校验、低置信度提示和失败后保留上下文。

## 二、范围

### 令牌与基础组件

- 扩展输入、状态标签、图片标注和进度摘要的组件令牌。
- 新增 `TextField` 和 `StatusBadge`。
- 扩展 `PhotoFrame` 支持与领域无关的归一化标注。
- 新增 `ProgressSummary`。

### 功能视图

- `GuideView` → `AreaGuideView`
- `AnnotatedPanorama` 的坐标和区域语义转换并入 `AreaGuideView`，具体绘制由 `PhotoFrame` 负责。
- 重构 `IdentificationReviewView`，统一照片、置信度、字段、提交和恢复动作。

### 页面控制器

- `ScanScreen` 继续负责图片来源汇合、识别和确认 API。
- 增加页面内识别错误与确认错误状态；不新增全局页面状态。
- 识别失败回到当前区域或旧识别草稿；确认失败保留当前表单实例和编辑值。

## 三、非目标

- 不修改后端接口、Pydantic 类型、模型提示词和本地规则引擎。
- 不修改 Zustand、`ScanPageStatus`、扫描区域推进和报告生成。
- 不迁移单品结果、报告、历史和首页。
- 不增加第三方依赖。
- 不确定最终品牌色、插画、图标、阴影、圆角细节和动效风格。

## 五、状态和事件

| 视图 | 输入 | 输出事件 | 状态所有者 |
|---|---|---|---|
| `AreaGuideView` | 区域、进度、全景图、已确认结果、错误 | `onStartCamera`、`onSelectFromAlbum`、`onSkip` | 挑战状态在 Store；错误和流程在页面 |
| `AnalysisView` | 当前单品照片、旁白 | 无 | `ScanScreen` |
| `IdentificationReviewView` | 草稿、单品照片、提交和错误 | `onConfirm`、`onRetake`、`onSelectFromAlbum` | 表单在视图；提交与错误在页面 |

## 六、异常与恢复

| 状态 | 保留内容 | 恢复动作 |
|---|---|---|
| 单品识别失败 | 当前区域、区域进度、已确认结果；存在旧草稿时保留旧草稿 | 重新拍照或从相册换图 |
| 相册取消 | 当前区域或识别草稿 | 留在原状态 |
| 低置信度 | 原照片和识别字段 | 核对编辑、重拍或换图 |
| 必填字段缺失 | 其他已编辑字段 | 就近补充产品名或品类 |
| 确认失败 | 全部用户编辑内容 | 原地再次确认或换图 |
| 跳过区域 | 已确认结果 | 下一地区；最后区域进入报告生成 |

## 七、无障碍检查

- 标注区域同时包含边框、序号和“当前拍摄区域”文字。
- 状态标签使用文字表达置信度和扫描结果，不只依赖颜色或 Emoji。
- 输入标签、必填状态、帮助和错误与输入控件关联。
- 主要操作最小高度 52，低优先级操作最小触控高度 44。
- 提交中通过 `accessibilityState.busy` 表达并阻止重复提交。
- 页面内错误使用 `accessibilityLiveRegion` 朗读，恢复动作保持可用。

## 八、响应式与平台检查

- 手机基准：390×844；检查长区域描述、长产品名和多行成分。
- Web 宽屏：页面内容最大宽度 720，照片最大宽度避免把操作推到首屏之外。
- 输入页面可随键盘滚动，底部操作不使用会遮挡输入框的固定定位。
- 相机和相册继续使用 Expo SDK 57 已有能力，不改变权限和图片 URI 处理。

## 九、回退策略

- 旧主题兼容层继续存在，未迁移页面不需要同步修改。
- 新视图只替换 `ScanScreen` 的展示导入；API 和 Store 不变。
- 旧 `GuideView` 和 `AnnotatedPanorama` 在新切片完成验证前不删除。
- 若需回退，可恢复旧视图导入，不需要迁移本地数据或后端响应。
