# 家庭化学品助手问答 — 可直接编码实施方案

> 版本：v1.0  
> 日期：2026-08-11  
> 阶段：Stage 4，待执行 agent 领取

## 1. 目标与范围

新增一个仓库内置的 LLM 问答页。用户从“问答”按钮进入，可发送文字或照片；后端读取当前库存产品、产品字段和相容性关系，再返回结构化回答。

MVP 必须满足：

- 文字和照片都是对话消息，不新增独立搜索模块；
- 回复明确区分“结合我家仓库”和“通用处理建议”；
- `CompatibilityEngine` 的禁止关系优先于 LLM 文本；
- LLM 不能编造产品、成分、用途或“绝对安全”结论；
- 不做对话持久化数据库，首期由移动端保存当前会话；
- 不支持误食、中毒、吸入、身体不适等事故处置建议。

## 2. 后端实施

### 2.1 新增领域模型

新增 `backend/app/models/assistant.py`：

```python
class AssistantHistoryMessage(BaseModel):
    role: Literal["user", "assistant"]
    text: str = Field(max_length=4000)

class AssistantProductAdvice(BaseModel):
    product_id: str = Field(alias="productId")
    recommendation: Literal["recommended", "not_recommended", "needs_information"]
    reason: str
    steps: list[str] = []
    cautions: list[str] = []

class AssistantSafetyWarning(BaseModel):
    severity: Literal["critical", "attention", "unknown"]
    title: str
    description: str
    relation_id: str | None = Field(None, alias="relationId")
    recommended_action: str

class AssistantResponse(BaseModel):
    answer: str
    needs_clarification: bool = Field(alias="needsClarification")
    clarification_questions: list[str] = Field(default_factory=list, alias="clarificationQuestions")
    inventory_advice: list[AssistantProductAdvice] = Field(default_factory=list, alias="inventoryAdvice")
    general_advice: list[str] = Field(default_factory=list, alias="generalAdvice")
    safety_warnings: list[AssistantSafetyWarning] = Field(default_factory=list, alias="safetyWarnings")
    out_of_scope: bool = Field(False, alias="outOfScope")
    evidence: list[str] = Field(default_factory=list)
```

`product_id` 必须来自数据库，不允许由 LLM 只返回产品名称。所有模型开启 `populate_by_name=True`，保持移动端 camelCase 契约。

- `MockAI` 返回固定可测试结果，覆盖：库存推荐、无合适库存、需要追问、禁止混用、超范围；
- `QwenAI` 使用结构化 JSON 输出，要求只引用传入的 `productId`；

### 2.3 安全编排服务

新增 `backend/app/services/assistant_service.py`，依赖：

- `InventoryService`：读取最多 500 个库存产品；
- `CompatibilityService`：读取全库关系；
- `CompatibilityEngine`：在返回前复核候选产品组合；
- `AIProvider`：理解问题并组织语言。

处理顺序固定为：

```text
校验输入与范围
  → 读取库存和相容性关系
  → LLM 生成结构化候选
  → 校验 productId 属于库存
  → CompatibilityEngine 复核
  → 过滤危险步骤/混用建议
  → 组装 AssistantResponse
```

安全编排规则：

1. 出现误食、中毒、吸入、身体不适等关键词，返回 `outOfScope=true`，不生成化学操作步骤；
2. 关系为 `critical` 时，强制生成 `safetyWarnings`，删除任何混合或连续使用步骤；
3. 产品 `information_status=needs_information` 时只能返回 `needs_information`；
4. LLM 返回未知 `productId`、不存在关系或绝对安全表述时，丢弃对应字段并追加不确定性说明；
5. `generalAdvice` 必须标记为非库存建议，不得生成“点击使用该产品”操作；
6. 没有库存候选时仍可给有限的通用建议，但必须明确“当前仓库无法确认合适产品”。

### 2.4 API 路由

新增 `backend/app/api/routes/assistant.py`，注册到 `backend/app/main.py`：

```text
POST /api/assistant/ask
Content-Type: multipart/form-data
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `question` | string | 是 | 当前问题，1–4000 字符 |
| `history` | string(JSON) | 否 | 最近最多 12 条消息 |
| `context_product_id` | string | 否 | 从产品详情进入时带入 |
| `image` | file | 否 | jpeg/png，压缩后不超过 5MB |

响应：`AssistantResponse`。

错误契约：

- `400 INVALID_ASSISTANT_INPUT`：问题为空、历史格式错误、图片类型不支持；
- `413 IMAGE_TOO_LARGE`：图片超过限制；
- `429 RATE_LIMITED`：复用限流器，key 为 `assistant:<client_ip>`，默认每分钟 8 次；
- `422 OUT_OF_SCOPE`：仍返回结构化拒答内容时使用 200；只有请求格式非法才返回 422；
- `502 AI_PROVIDER_ERROR`：AI 服务失败，客户端可重试；
- `504 AI_PROVIDER_TIMEOUT`：超时，客户端保留草稿。

所有 `/api/assistant/*` 自动经过现有 Bearer 鉴权和 CORS 中间件。

### 3.2 API 客户端

```ts
ask(input: {
  question: string;
  history: AssistantHistoryMessage[];
  contextProductId?: string;
  imageUri?: string;
}): Promise<AssistantResponse>
```

实现要求：

- 使用现有 `apiClient` 的 `authHeaders()`；
- 使用 `FormData`；有文件时追加 `{ uri, name, type }`；
- 不手动设置 `Content-Type`，让 fetch 自动生成 multipart boundary；
- 复用 `photoAssetService.compressForUpload`，最长边和质量沿用识别上传规则；
- 15 秒超时，沿用 `mapMutationError` 的错误文案体系；
- 发送中禁用重复发送。

### 3.3 Store

新增 `mobile/src/store/assistantStore.ts`，状态：

```ts
type AssistantMessage = {
  id: string;
  role: 'user' | 'assistant';
  text: string;
  imageUri?: string;
  response?: AssistantResponse;
};

type AssistantState = {
  messages: AssistantMessage[];
  draft: string;
  pendingImageUri: string | null;
  contextProductId?: string;
  sending: boolean;
  error: string | null;
  send: () => Promise<void>;
  attachPhoto: (uri: string) => void;
  clearAttachment: () => void;
  reset: () => void;
};
```

规则：

- 先将用户消息加入本地列表，再调用 API；失败时保留消息并显示重试；
- 成功后追加助手消息；
- history 只发送最近 12 条，避免请求无限增长；
- 页面离开后本次会话保留在 Store，重新进入可继续；
- 不把照片永久保存到产品封面或库存资产目录。

负责模型、AI Provider、AssistantService、路由、限流、后端测试。不得修改移动端。

### Agent B：移动端问答页

负责导航、API client、Store、问答组件、页面和移动端测试。依赖 Agent A 的响应契约；可先使用 Mock API。
