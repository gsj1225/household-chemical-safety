## 一、范围与非目标

本线框增量只处理已经确认的六组异常恢复状态：

1. 首页创建检查失败。
2. 全景上传、网络或模型超时。
3. 全景照片本身无效。
4. 细拍识别失败。
5. 产品确认写入失败。
6. 报告生成失败。

原有相机权限、全景零区域、全部跳过和退出确认线框继续有效，本次不重复绘制。

本阶段不决定最终颜色、图标、阴影、圆角风格、动画，也不修改 React Native 应用代码。

## 二、全局布局规则

- 目标设备：安卓手机；基准画板 390×844。
- 结构顺序：安全区 → 导航/进度 → 被保留的任务上下文 → 错误解释 → 恢复动作。
- 错误卡紧邻发生错误的上下文，不覆盖整个页面。
- 页面底部最多一个深色主操作；等价替代方案使用描边次操作。
- 所有错误状态同时使用符号、标题和说明，不依赖颜色。
- 长错误文案允许页面纵向滚动；固定底部动作不得遮挡内容。

## 三、动作层级

| 场景 | 主操作 | 次操作 | 低优先级操作 |
|---|---|---|---|
| 创建失败 | 重新连接并开始 | 查看历史报告 | 无 |
| 全景请求失败 | 重试分析这张照片 | 换一张照片 | 返回全景说明 |
| 照片无效 | 重新拍一张 | 从相册换一张 | 仍然重试这张 |
| 细拍识别失败 | 重试识别这张照片 | 重拍、相册换图 | 跳过此区域 |
| 确认失败 | 再次确认并评估 | 返回核对 | 无 |
| 报告失败 | 重新生成本场景报告 | 查看已确认结果 | 无 |

## 四、页面组

### 01 首页创建失败

- 目标：保留首页理解成本，让用户明确只是服务暂不可达。
- 信息顺序：产品价值 → 原首页上下文 → 行内错误卡 → 重试 → 历史。
- 状态变体：连接失败、服务忙、请求过频。

### 02 全景请求失败

- 目标：让用户看到刚才的照片仍在，并能一键重试同一张。
- 信息顺序：阶段 → 原图 → 错误原因 → 追踪号 → 重试 → 换图/返回。
- 状态变体：上传失败、请求超时、模型暂不可用。

### 03 全景照片无效

- 目标：区分照片质量问题和服务问题，避免无意义重复分析。
- 信息顺序：无效原图 → 缺失证据 → 拍摄建议 → 重拍 → 相册 → 低优先级原图重试。
- 状态变体：图片过大、格式不支持、模糊、过暗、主体严重遮挡。

### 04 细拍识别失败

- 目标：同时保留全景定位、当前区域进度和失败细拍。
- 信息顺序：区域进度 → 原图定位 → 失败细拍 → 错误解释 → 原图重试 → 重拍/相册 → 跳过。
- 状态变体：首次识别失败、替换照片失败；后者继续显示旧草稿。

### 05 产品确认失败

- 目标：证明用户修改没有丢失，并阻止重复识别。
- 信息顺序：照片 → 编辑字段 → 行内错误 → 追踪号 → 再次确认。
- 状态变体：服务失败、challenge 失效；失效时主操作改为返回首页新建检查。

### 06 报告生成失败

- 目标：让用户确信已确认结果仍在，重试只重新汇总报告。
- 信息顺序：阶段结论 → 三项统计 → 已确认结果 → 错误解释 → 重新生成 → 查看结果。
- 状态变体：网络失败、超时、服务异常。

## 五、跨页面一致性

| 检查 | 决策 |
|---|---|
| 是否保留上下文 | 照片、区域、草稿或结果至少保留一种，并置于错误卡之前 |
| 主操作是否唯一 | 每页只有一个深色按钮 |
| 错误是否可理解 | 标题说明发生了什么，正文说明什么没有丢失 |
| 是否暴露开发语言 | 不显示 API 地址、端口、堆栈或密钥 |
| 是否可定位服务问题 | 有追踪号时显示前 8 位 |
| 是否防止重复成本 | 重试复用 challenge；报告重试不重新识别照片 |
| 是否兼顾无障碍 | 错误用符号、标题、正文共同表达；触控目标不小于 44×44 |
